# DOMAIN.md — solar-v2

Seed: see `docs/DOMAIN.md` (canonical). Realizes the **distilled DDD domain model**:
bounded contexts become polars year-series with readable domain names. NO formula
parsing/evaluation in the compute path (that is solar-v1's job — v2 is the
independent reimplementation that makes G2 meaningful).

## Architecture (settled 2026-07-26 after two rejected interpreter-clone attempts)

- `schedule.py` — static unit schedule (1087 steps; generated by
  `scripts/gen_schedule.py`, ranges expanded to every cell in the rectangle).
  Coarse steps: (sheet, row) and intra-sheet SCC groups (sheet, (rows)).
  Fine steps: (sheet, row, col) — 31 year-shifted MUTUAL rows （损益 tax block ↔
  财务计划 ↔ 还贷 20/21 ↔ 成本 13/16/21 ↔ 现金流量 57) are a cross-sheet cycle at
  row granularity but acyclic per cell, so they're scheduled per column (802
  fine steps). Modules register coarse `UNITS: dict[Step, StepFn]` and fine
  `UNITS_FINE: dict[(sheet,row), FineStepFn]` (fn(params, view, col)).
- `pipeline.py` — `run_pipeline(params, registry, dag_path, fine_registry=…)`:
  loads literal givens, executes steps in schedule order; each step reads only
  already-computed values through the ValueView. Output filtered to dag node
  ids (a step emitting a cell the workbook leaves blank is dropped).
- `params.py` — ProjectParameters as a frozen `@dataclass` with named fields;
  literals from the dag (the givens), 参数表's derived scalars re-implemented as
  named computations (constant folding as domain code).
- Context modules: `param_steps.py` （参数表), `invest.py` （投资计划/InvestmentPlanning),
  `debt.py` （还贷/DebtService), `cost.py` （成本/Cost), `pnl.py` （损益/PnL),
  `cashflow.py` （现金流量/CashFlow), `finplan.py` （财务计划/FinancialPlan),
  `balance.py` （资产负债/BalanceSheet), `valuation.py` （估值结果+指标汇总/Valuation).
- `api.py` — `compute(settings) -> NodeValues`: full pipeline over all modules,
  keyed by dag node id for the G2 node-by-node diff vs solar-v1.
- Error policy: error cells (cached = Excel error) emit `ErrorValue` with the same
  string; error literals in DEAD branches are never evaluated (lazy IF) — the live
  value is computed (e.g. 财务计划!E36 = 0).

## Test oracle (tests/helpers.py — dev only, never in compute path)

Each slice verifies its sheet against the workbook cached values with foreign
sheets substituted by cached-value emitters (coarse `oracle_registry` + fine
`oracle_fine_registry`); integration (tests/test_g2_integration.py) runs the
full pipeline with ZERO oracle substitution — 0/6560 nodes diverge from the
workbook, and `solar-cli verify` path 1.2 confirms v2 == v1 node-by-node.

## Known workbook anomalies (documented, computed honestly — never special-cased)

- 损益 row 7: G7/H7 = row6/(1+vat), but I7+ freezes at H7 (column-specific
  formula variation breaking the shifted-identical pattern).
- 损益!AF16 is MIN(G16:AE16), not a SUM like other AF aggregates.
- 参数表!C15 static investment includes the first land-rent PAYMENT (C68),
  not the annual rent (C59).
- Junk defined names aa/ab/ac/b/cc/i/j point to 投资计划 aux literals and are
  used by formulas; 存款利率/公益金/流动资金贷款比例 are #REF!-broken names.

## Simplifications

1. **Year-series collapse** (design default): every column-shifted identical formula
   row is ONE polars series with a domain name, not N cells of logic. 208 series
   cover 4705 of 6560 nodes.
2. **Constant folding**: 参数表's derived scalars (C8, C15's inputs, C18, C23, C24,
   C25, C29, C43, C47, C59, C61, C73) computed once as named Python in params.py /
   param_steps.py instead of re-evaluated per consumer.
3. **Dead-branch elimination**: 财务计划!E36's `#REF!` branch is provably dead
   (blank D28/E28 → first IF condition true) — the live value 0 is computed
   directly. 损益 row 12 VAT-refund branch is provably 0 (vat_exempt_year=2020
   predates all operating years) — computed as an always-false predicate, not
   special-cased away.
